### 25.11.2026 (המשך) – זרימת ההדפסה של MagnetOti (אחרי צפייה בשחר עובד)
**רקע:** צפיתי בשחר מדפיס ב-MagnetOti (פירוט ב-REFERENCE-MAGNETOTI.md › זרימת עבודה אמיתית). שחר בחר: "זרימת
ההדפסה הראשית" (לא עכשיו: מסך הגדלות, Gamma, Properties).
**נעשה:**
- **תצוגה מקדימה להדפסה** (`ui/print_preview.py`): כל הדפים, לחיצה בוחרת/מבטלת דף, כל הדפים / טווח, זום, סיכום
  (דפים, נבחרו, מגנטים, גודל דף), "הדפס N דפים" / "שמירה כ-JPEG". הדפים נבנים ברקע (`services/page_builder.py`,
  כל תמונה מרונדרת פעם אחת, עותקים צמודים) עם חלון התקדמות "יוצר דפי הדפסה…". מדפיסים את הדפים שנבחרו
  (`PrintJob.pages_ready`), והספירה לכל כרטיס לפי המגנטים שבדפים האלה.
- **סיכום בפאנל:** סה"כ להדפסה · קיבולת לדף r×c · סה"כ עמודים · "יש X מקומות פנויים בדף האחרון" (אדום) /
  "אין מקומות פנויים — הדפים מלאים" (ירוק) · גודל הדף במ"מ.
- **"התחל מ1 / התחל מ0"** – כמות התחלתית לתמונות שמעלים (ברירת מחדל 1, כמו ששחר עובד); כרטיסים שלא נגעו בהם מתעדכנים.
- **גודל מדיה מהדרייבר:** `media_size_mm` מוצא בדרייבר את הנייר שתואם ל-15x20 (CP-D80DW: 158×206), הפריסה נבנית על
  הגודל הזה (`SheetSpec.paper_mm`) והעמוד נשלח בגודל של הדרייבר (`_driver_page_size`). PDF – הגודל הנומינלי.
- **הכמויות נשארות אחרי הדפסה** (כמו MagnetOti); התג בכרטיס מראה "הודפס ×n".
- **"הורדה (JPEG)"** – דפי ההדפסה כקובצי JPEG ב-300 DPI לתיקייה.
**אומת:** 41 בדיקות (חדשות: תצוגה מקדימה – הכול / דף אחד / JPEG, מתג ההתחלה, דיאלוג הבחירה, גודל מדיה מדרייבר מדומה).
צילומים: `screenshots/19_print_preview.png`, `20_summary_empty_slots.png`.
**פתוח:** לאמת מול CP-D80DW אמיתית שהדרייבר אכן מחזיר 158×206 ושההדפסה ממלאת את הדף · מסך הגדלות · Gamma · Properties.

### 25.11.2026 – מסך ראשי בסגנון MagnetOti + הדפסת דף 15x20 (2×2) + בהיר/כהה
**רקע:** שחר הראה את MagnetOti (התוכנה שהוא עובד איתה היום) – "ככה התוכנה אמורה להיראות". רפרנס מלא:
[REFERENCE-MAGNETOTI.md](REFERENCE-MAGNETOTI.md). החלטות שחר: כמו MagnetOti + תור חי · מצב ראשי = דף 15x20
עם 2×2 · ערכה בהירה/כהה/אוטומטית.
**נעשה:**
- ליבה: `PaperSize`/`PAPER_SIZES` (15x20=6x8", 10x15, 13x18, 20x25, A4) · `SheetSpec` + `build_grid_sheets`
  (שורות × עמודות, שוליים במ"מ, סימוני חיתוך דק/בינוני/עבה, אורך+רוחב באותו דף, התאמה בלי חיתוך) ·
  `PrintMode.SHEET` (ברירת מחדל) · עותקים לכל תמונה (`photo_copies`) · זוג מסגרות PNG (`frame_landscape`) ·
  מחוונים חשיפה/ניגודיות/חדות (`framer.adjust`, משולבים ב-photo filter).
- בקר התור: עבודה אחת יכולה לכסות כמה כרטיסים (`tag = "id1,id2,…"`, `items_of`).
- `services/thumbnails.py`: רינדור "מגנט מוגמר" ממוזער ברקע (JPEG draft) עם generation לביטול עבודה ישנה;
  נסגר לבד כשאין עבודה ונשמר ב-`_RUNNING` (Qt מפיל את התהליך אם QThread נמחק בזמן ריצה).
- `ui/components/photo_grid.py`: רשת כרטיסים (☆, תג סטטוס, − n +), מצב ריק "גררו תמונות לכאן".
- `ui/main_window.py` נכתב מחדש: סרגל עליון (דפים, עלות, איפוס אירוע, זום), סרגל כלים (העלאה, גודל, שיפור,
  מסגרות: תבנית / "מסגרת אורך" / "מסגרת רוחב" / ללא, ⚡ תור חי), פאנל "הגדרות הדפסה" (מצב, מדפסת, נייר,
  שורות×עמודות, סימוני חיתוך, שוליים, Hot Folder), שורת סטטוס עם מחוונים ו"היום: X דפים".
  הדפסה = כל העותקים כעבודה אחת; אחרי הצלחה העותקים מתאפסים. Hot Folder במצב דף מחכה לדף מלא.
- ערכות צבעים: `theme.set_mode(auto/light/dark)` לפני בניית החלון; בחירה בהגדרות (נכנס לתוקף בהפעלה הבאה);
  עלות לדף בהגדרות.
**אומת:** 38 בדיקות (חדשות: `test_sheets.py`, `test_main_screen.py` – כולל PDF אמיתי של 2 דפי 15x20 ומונים).
צילומים: `screenshots/16–18`.
**פתוח:** בדיקה עם Mitsubishi CP-D80DW אמיתית (גודל נייר 6x8 בדרייבר) · "פרצופים"/"אפקטים"/"הגדלות" של MagnetOti לא מומשו.

### 25.11.2026 – תיקון התצוגה החיה (Codespaces)
**רקע:** שחר: "לא מצליח לפתוח" – התוכנה מופיעה אבל תקועה.
**נמצא:** (1) `setup.sh` נפל כבר ב-`apt-get update`: בתמונת הבסיס יש מקור apt של Yarn עם מפתח שפג → `set -e`
עצר הכול (נחשף ב-CI חדש שבונה את ה-devcontainer). (2) שרת ה-VNC המובנה של Qt שולח פיקסלים בסדר בתים
שגוי (טורקיז → צהוב ב-noVNC) ותמיכת המקלדת שלו חלשה.
**נעשה:** setup מסיר את מקור Yarn ולא נכשל על מקורות צד שלישי; marker של התקנה + `start.sh` משלים
התקנה חסרה לבד; `live.py` מפעיל את עצמו מחדש כשקבצי `.devcontainer/` מתעדכנים. מעבר ל-Xvfb + openbox +
x11vnc (`-add_keysyms`) + noVNC; התוכנה על xcb, נפתחת ממוקסמת (`MAGNETSTUDIO_START_MAXIMIZED`).
CI חדש: `.github/workflows/devcontainer.yml` בונה את ה-devcontainer כמו Codespaces ומריץ בדיקת עשן.
**אומת (מקומית, Chrome אמיתי דרך noVNC):** צבעים נכונים, חלונות עם מסגרת, קליק פותח דיאלוג, הקלדה
בעברית במקלדת אמיתית ("שלום") מגיעה לשדה.
עוד שני באגים שנחשפו ב-CI של ה-devcontainer: הפעלה כפולה (postStart + ידנית) התנגשה בשאריות
(Xvfb lock, פורטים) → start.sh מחכה לסיום הקודם ו-live.py מנקה שאריות; והניקוי עם `pkill -f openbox`
הרג כל shell שהמילה הופיעה בשורת הפקודה שלו → התאמה מדויקת בלבד (`pkill -x`, דפוסים מעוגנים).
**אומת ב-CI (devcontainer זהה ל-Codespaces):** setup מסתיים, 6080 → 200, VNC עונה (RFB 003.008),
Xvfb/x11vnc/התוכנה רצים, אף רכיב לא נופל.
**פתוח:** Codespace קיים שנוצר לפני התיקון – למחוק וליצור מחדש.

### 24.11.2026 (המשך) – תצוגה חיה בדפדפן (GitHub Codespaces)
**רקע:** שחר רוצה לבדוק כל שינוי "בלייב", בלי להתקין כלום במחשב (גם לא GitHub Desktop / Python).
**נעשה:** `.devcontainer/` – Codespace שמריץ את התוכנה בענן ומציג אותה בלשונית דפדפן:
Qt על פלטפורמת `vnc` (מובנית ב-PyQt6, בלי X/שולחן עבודה) → websockify + noVNC על פורט 6080 (נפתח אוטומטית).
`live.py`: מפעיל מחדש כשהקוד משתנה או כשהתוכנה נסגרת/קורסת; כל 20 ש' `git pull --ff-only` (רק כשאין
עריכות מקומיות) ומתקין תלויות מחדש אם `pyproject.toml` השתנה. נתוני משתמש ב-`~/.magnetstudio-live`.
קישור: https://codespaces.new/gpzboy-creator/magnet-studio?quickstart=1
**החלטות:** VNC של Qt במקום desktop-lite – פחות חלקים, אין צורך ב-X11/מנהל חלונות; noVNC עם reconnect
כדי שהלשונית תתחבר לבד אחרי כל הפעלה מחדש.
**אומת (בסביבת הפיתוח, לא ב-Codespaces עצמו):** התוכנה עולה על VNC, צילום מסך דרך VNC, noVNC מחזיר 200,
websocket 101, קליק פותח דיאלוג קבצים, שינוי קובץ → הפעלה מחדש תוך ~2 ש', `pull()` מושך commit חדש,
לא מושך שוב, ולא נוגע כשיש עריכות מקומיות.
**פתוח:** הרצה ראשונה ב-Codespaces אמיתי (התקנת חבילות המערכת ב-setup.sh) · הקלדה בעברית דרך noVNC לא נבדקה.

### 24.11.2026 (המשך) – מפעיל שמתעדכן לבד (בלי Python, בלי GitHub Desktop)
**רקע:** שחר לא יכול להתקין GitHub Desktop, ורוצה לבדוק גרסאות בלי להוריד ידנית כל פעם.
בחר: אפליקציה מוכנה (בלי Python) + מפתח GitHub לקריאה בלבד.
**נעשה:** `launcher/MagnetStudio.bat` (קובץ אחד: batch + PowerShell מובנה ב-Windows) ו-`launcher/MagnetStudio.command`
(Mac: curl + JavaScript של macOS לפענוח JSON + Keychain). בכל הפעלה: בודק את שחרור `latest`, מוריד ומחליף אם
יש build חדש (מזהה ב-`MagnetStudio-app/build-id.txt`), ומפעיל. בלי אינטרנט → מפעיל את מה שיש.
המפתח נשאל פעם אחת: Windows – מוצפן ב-DPAPI למשתמש (`%LOCALAPPDATA%\MagnetStudio\updater-token.dat`);
Mac – Keychain. מפתח שנדחה (401/403/404) → מבקש חדש. המפעילים מצורפים לשחרור כ-zip.
**CI:** job `launcher` – מריץ את שניהם מול השחרור האמיתי מתיקייה עם רווח, פעמיים (הורדה, ואז "up to date").
השחרור מתעדכן במקום (תג זז, `--clobber`) ולא נמחק – פלטפורמה שה-build שלה נכשל שומרת את הגרסה הקודמת.
**נמצא בדרך:** `#>` בשורת ההערה הראשונה סגר את בלוק ההערה של PowerShell מוקדם. GitHub לפעמים לא מקצה
מכונת Mac (capacity) – לכן הפרסום כבר לא תלוי בהצלחת כל הפלטפורמות.
**אומת:** CI – Windows: הורדה 61MB, פריסה, הפעלה, ובהרצה שנייה "up to date". Mac: עבר ב-run הקודם.

### 24.11.2026 – סקירת ארכיטקטורה: שלבים 1–6 + ריפו ב-GitHub
**רקע:** שחר ביקש סקירה של המבנה ("האם זה מבנה טוב? סטנדרטי?"). נמצאו 6 נקודות לשיפור
(פירוט מלא ב-[ARCHITECTURE.md › סקירה](ARCHITECTURE.md#סקירת-ארכיטקטורה-24112026)). כולן בוצעו היום,
כל שלב כ-commit נפרד, והקוד הועלה לריפו פרטי `gpzboy-creator/magnet-studio`.

| שלב | commit | מה |
|-----|--------|----|
| 1–2 | (לפני הריפו, נכלל ב-Baseline `54843cf`) | שמירת הגדרות/מונה מיידית ואטומית + לוג מתחלף + hooks לחריגות |
| 6 | `a51a808` | חבילת Python אמיתית (`pyproject.toml`, `magnetstudio/`), מעבר ל-pytest |
| 5 | `c475600` | פיצול `frame_generator.py` (1,170 שורות) לחבילה `generator/` |
| 4 | `f450996` | תיקיות משתמש, מפתח API ב-keychain, core בלי Qt, בניית PyInstaller |
| 3 | `8122a54` | `PrintQueueController` – מצב התור במקום אחד |

**החלטות:**
- **שכבות:** `core/` + `generator/` בלי Qt בכלל (נאכף בבדיקה שחוסמת import של PyQt6) ·
  `services/` = Qt בלי widgets (workers, הדפסה, בקר התור) · `ui/` = widgets בלבד.
- **נתיבים:** הכול דרך `magnetstudio/paths.py`. משאבים מצורפים לקריאה בלבד (גם ב-PyInstaller
  דרך `sys._MEIPASS`); נתוני משתמש בתיקיות מערכת ההפעלה (platformdirs). `MAGNETSTUDIO_HOME` מעביר הכול
  לתיקייה אחת (בדיקות / התקנה ניידת ב-USB).
- **מיגרציה:** בהפעלה ראשונה מועתקים (לא מועברים, לא דורסים) `config/settings.json`, תבניות וגופנים
  של המשתמש מהמבנה הישן. קובץ סימון `.migrated-from-legacy` מונע ריצה חוזרת.
- **מפתח Gemini:** ב-Keychain / Credential Manager דרך `keyring`. סדר: משתנה סביבה → keychain →
  ערך ישן בהגדרות. אין keychain (Linux בלי שרת) → נשאר בהגדרות, האפליקציה עובדת.
- **תור הדפסה:** מצב אחד (`Stage`): INCOMING → QUEUED → ENHANCING → COMPOSING → SPOOLING → PRINTED / FAILED.
  החלון רק מציג; `job_factory` שלו קובע מה מדפיסים לפי הבחירות בממשק.
- **כיבוי:** Ctrl+C / SIGTERM סוגרים את החלון כרגיל (הגדרות נשמרות). לפני זה ה-hook לחריגות "בלע"
  את ה-KeyboardInterrupt והאפליקציה לא נסגרה.

**נמצא בדרך (באגים שתוקנו):**
- בלי `sys.excepthook` מותקן, PyQt6 מפיל את כל האפליקציה על חריגה בתוך slot (exit -6) – באירוע זה
  אומר תור שאבד. תוקן בשלב 2.
- בדיקה שסגרה חלון כתבה הגדרות בדיקה לקובץ ההגדרות **האמיתי**. תוקן: כל בדיקה מקבלת תיקיית בית זמנית
  (conftest), ו-keyring בזיכרון.
- `test_printer` יצר `QApplication` שני → segfault ברגע שבדיקה אחרת יצרה את הראשון.
- קבצי `_generated` נכתבו לתוך תיקיית החבילה (ונכנסו ל-commit). עכשיו בתיקיית הנתונים של המשתמש.
- בדיקת ביצועים של ה-Enhancer (תמונת 24MP < 150ms) לפעמים נכשלת ב-1ms תחת עומס – flaky, לא באג.

**אומת:** 26 בדיקות עוברות (~45 ש') · `python -m magnetstudio` ו-`magnetstudio` עולים ·
בניית PyInstaller (258MB) עולה offscreen, משתמשת רק בתיקיות המשתמש ונסגרת נקי ב-SIGTERM.
